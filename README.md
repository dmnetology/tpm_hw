# Отчёт по Домашнему заданию 4. Синхронизация потоков

Несколько потоков одновременно работают с общим коллектором данных: пишут элементы, разбирают их из общего списка и обрабатывают. Все операции над общими данными защищены `synchronized`, координация потоков построена на `wait()`/`notifyAll()`, перенос элементов между двумя коллекторами выполняется без взаимной блокировки.

## Ход работы

1. **DataCollector** — общий ресурс: список собранных элементов, набор ключей обработанных элементов и счётчик `processedCount`. Методы объявлены `synchronized`, поэтому каждая операция над общими данными выполняется целиком одним потоком: `collectItem()` добавляет элемент и уведомляет ждущие потоки (`notifyAll()`), `incrementProcessed()` увеличивает счётчик, `isAlreadyProcessed(key)` проверяет, обрабатывался ли элемент.
2. **Координация:** потоки-обработчики забирают данные методом `takeNext()`; если общий список пуст, поток засыпает в `wait()`, производитель после добавления элемента будит его через `notifyAll()`. Проверка ключа и пометка его как обработанного выполняются под одним замком — повторная обработка исключена.
3. **Нагрузочный тест:** 4 потока-сборщика × 250 элементов против 4 обработчиков; затем сравнение времени: 8 потоков × 50 000 записей в синхронизированный и несинхронизированный список, по 3 замера после прогрева JIT.
4. **Предотвращение deadlock:** два потока переносят элементы между двумя коллекторами навстречу друг другу. Метод `transferItems()` захватывает сразу два замка, но всегда в одном порядке — сначала коллектор с меньшим `identityHashCode`, поэтому встречные переносы не блокируют друг друга навсегда (альтернатива — `tryLock` с тайм-аутом).

## Результат (вывод программы)

```text
=== DataCollector: одновременный доступ, wait() и notifyAll() ===
Собрано элементов: 1000 (ожидалось 1000)
Обработано: 250, пропущено повторов: 750 — нет дублирования работы: true
Список после обработки пуст: true

=== Сравнение: synchronized и несинхронизированные операции ===
Среднее: synchronized 23,4 мс, без синхронизации 5,4 мс
Итоговый счётчик synchronized: 400000 из 400000 — верно: true
Итоговый счётчик без синхронизации: 164248 — потеряно 235752 записей, исключений: 0

=== Предотвращение deadlock: единый порядок захвата замков ===
Целостность данных: всего элементов по-прежнему 200 из 200: true
```

## Что показали замеры

- несинхронизированный вариант быстрее (5,4 мс против 23,4 мс), но это пример некорректной ситуации: счётчик 164 248 вместо 400 000 — около 60 % записей потеряно из-за гонки данных;
- `synchronized` даёт корректный результат ценой накладных расходов на захват монитора и ожидание потоков;
- при встречных переносах взаимной блокировки не возникло, целостность данных сохранена — обе стороны захватывают замки в одном и том же порядке.
