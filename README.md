# Отчёт по Домашнему заданию 3. Параллелизм и параллельность

Список из 1 000 000 случайных чисел обрабатывается тремя операциями — фильтрация (только чётные), преобразование (умножение на 2), агрегация (сумма) — последовательно через `stream()` и параллельно через `parallelStream()`.

## Ход работы

1. **Сервис** `StreamBenchmarkService` создаёт список из 1 000 000 случайных чисел и выводит параметры окружения: количество ядер и параллелизм `ForkJoinPool.commonPool()` (потоков = ядра − 1).
2. **Конвейер одинаковый для обоих вариантов:** `filter(чётные)` → `mapToLong(n -> n * 2L)` → `sum()`, замер `System.nanoTime()`. Каждый вариант выполняется 3 раза, перед замерами — один прогревочный запуск (без него первые вызовы искажены прогревом JIT и сравнение получается некорректным).
3. **Вывод результатов:** время каждого запуска, среднее время, сумма обоих вариантов и проверка совпадения результатов.

## Результат (вывод программы)

```text
Ядер у процессора: 16, параллелизм ForkJoinPool.commonPool(): 15
Запуск 1: stream() 9,8 мс, parallelStream() 2,0 мс
Запуск 2: stream() 11,0 мс, parallelStream() 1,7 мс
Запуск 3: stream() 10,2 мс, parallelStream() 1,8 мс
Среднее: stream() 10,3 мс, parallelStream() 1,9 мс
Сумма: последовательный = -3509415418992, параллельный = -3509415418992, совпадают: true
```

Параллельный вариант быстрее примерно в 5 раз.

## Почему parallelStream() быстрее

- операция процессорная (CPU-bound) и элементы независимы, объём (1 000 000) оправдывает разбиение на подзадачи;
- `ArrayList` делится сплитератором на равные диапазоны индексов почти без пересчётов;
- `parallelStream()` выполняется в `ForkJoinPool.commonPool()` (15 потоков) с балансировкой work stealing, части конвейера действительно выполняются одновременно на разных ядрах.

## Когда параллельный поток выигрыша не даёт

- малый объём данных и поэтому разбиение и координация потоков дороже самой работы;
- операции I/O или блокирующие, т.е. потоки пула простаивают;
- источник данных делится плохо или критичен строгий порядок;
- `commonPool` уже занят другими задачами приложения.
