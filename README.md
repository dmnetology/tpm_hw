# Отчёт по Домашнему заданию 5. Блокировка доступа к ресурсам. ReentrantLock и Condition

Ограниченный буфер фиксированного размера `BoundedBuffer` - несколько потоков-производителей кладут в него элементы, несколько потребителей извлекают. Синхронизация построена на паре ReentrantLock/Condition; для сравнения тот же буфер реализован на synchronized и wait()/notifyAll().

## Ход работы

1. **BoundedBuffer** — циклический массив фиксированного размера, все операции выполняются под одним ReentrantLock (lock() в начале, unlock() в finally). put() добавляет элемент, take() извлекает; если буфер полон, производитель ждёт, если пуст — потребитель.
2. **Два условия на одном замке:** notFull для производителей и notEmpty для потребителей, у каждого своя очередь ожидания. put() будит одного потребителя (notEmpty.signal()), take() будит одного производителя (notFull.signal()) — лишних пробуждений нет. finishProduction() через signalAll() сообщает потребителям, что подача закончена, и потребители завершают работу.
3. **Производители и потребители:** BufferProducer кладёт заданное число последовательных значений (у каждого потока свой диапазон), BufferConsumer извлекает значения, пока буфер не пуст. Этап 1 — буфер ёмкости 10, 3 производителя × 500 элементов против 3 потребителей.
4. **Сравнение производительности:** тот же буфер на synchronized/wait()/notifyAll() — там одно общее условие для обеих сторон, будить приходится всех. Одинаковый нагрузочный прогон (4 производителя × 25 000 и 4 потребителя, буфер ёмкости 50) выполняется на обоих вариантах, по 3 замера после прогрева JIT.

## Преимущества и недостатки ReentrantLock и Condition

- замеры не дают устойчивого выигрыша по скорости; в этом прогоне ReentrantLock в среднем быстрее (46,9 против 53,3 мс), но разброс запусков больше разницы — при коротких критических секциях оба варианта дают сопоставимую скорость;
- преимущество ReentrantLock/Condition в точности управления; два раздельных условия на одном замке, точечный сигнал одному потоку вместо notifyAll(), tryLock() с тайм-аутом, справедливый режим раздачи замка;
- недостаток — ручное управление; unlock() обязательно в finally, иначе после исключения замок никогда не освободится; кода заметно больше, чем с synchronized.
