# Отчёт по Домашнему заданию 2. Жизненный цикл потока

Цель: отслеживать изменения состояний потоков и синхронизировать их выполнение с помощью метода `join()`.
Выполнено в ветке `task2` на ветвлении от решения ДЗ 1.

## Ход работы

1. **Три потока, каждый проходит через разные состояния.** Все работают с общим монитором-замком:
   - `LockHolder` — фаза полезной работы без сна (RUNNABLE), затем захватывает монитор и засыпает внутри `synchronized` (TIMED_WAITING, при этом монитор не отпускается), в конце пробуждает ожидающие потоки (`notifyAll()`);
   - `WaitingWorker` — первым (по порядку старта) входит в `wait()` (WAITING), после уведомления получает монитор и завершается;
   - `BlockedWorker` — пытается войти в критическую секцию, пока монитор занят `LockHolder` (BLOCKED), после его освобождения получает монитор и завершается.
2. **Наблюдение за состояниями.** Отдельный поток `ThreadStateObserver` каждые 100 мс опрашивает `getState()` всех трёх потоков и печатает в консоль каждое изменение состояния; когда все наблюдаемые потоки в TERMINATED — завершается.
3. **Синхронизация.** `ThreadLifecycleService` управляет порядком старта (waiting → пауза → holder/blocked, чтобы сценарий состояний был воспроизводимым) и ожидает завершения всех рабочих потоков методом `join()` (основной поток и завершение наблюдателя).

## Результат (фрагмент консоли)

```text
[наблюдатель] LockHolder: NEW
[наблюдатель] WaitingWorker: NEW
[наблюдатель] BlockedWorker: NEW
[наблюдатель] WaitingWorker: TIMED_WAITING
[наблюдатель] WaitingWorker: WAITING
[наблюдатель] LockHolder: RUNNABLE
[наблюдатель] LockHolder: TIMED_WAITING
[наблюдатель] BlockedWorker: BLOCKED
[наблюдатель] LockHolder: TERMINATED
[наблюдатель] WaitingWorker: TERMINATED
[наблюдатель] BlockedWorker: RUNNABLE
[наблюдатель] BlockedWorker: TERMINATED
```

В консоли показаны все шесть состояний потока: NEW, RUNNABLE, WAITING, BLOCKED, TIMED_WAITING, TERMINATED.
